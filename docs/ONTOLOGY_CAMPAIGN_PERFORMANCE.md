## Source-first benchmark

The official `https://one-piece.com/sitemap.xml` lists 15,821 URLs, including 996 character profile URLs. Canonical names, Japanese labels, aliases, and identifiers produced 686 unique exact character matches. The revised matcher also routes embedded identifier/name candidates to review: 126 profiles are now in the identity review queue and 184 remain unmatched. It never merges a substring match automatically. The sitemap was fetched once; `/robots.txt` returned 404, so no published rules were found at crawl time. Profile downloads use four bounded workers with a shared minimum one-second interval between request starts. Three additional indexed profiles were fetched specifically for batch 055 identity review.

The representative sample reuses batch 054’s same 20 entities. The old pass took 535 s to record partial reviews. The source index found official profile pages for 12/20 entities. Those 12 cold page requests took 17.414 s total HTTP time (1.451 s mean); with the sitemap and one robots.txt check, that is 14 HTTP requests for the 20-entity sample (0.70 requests/entity, including the shared index requests). No search-engine queries were needed, and source parsing used 0 LLM calls/entity. After caching, extraction and matching took 0.1117 s, plus the shared 0.1643 s name-index build. The strictly scoped parser produced 9 factual candidates across those pages. Their URLs, exact field text, and document hashes are present for 9/9 candidates. **0 were applied to RDF** in this throughput benchmark; the other 8 sample entities still require research. The source-first result is therefore not yet equivalent to 20 completed reviews, and the two rates are not directly comparable. No speedup in verified entities/hour is claimed.

One early parser version read related-character cards outside the focal profile block. That version’s 23 candidates were superseded and were not used for RDF changes. The parser now scopes extraction to the focal profile, skips nested related-character cards, supports the older profile layout, preserves `<br>` boundaries, and retains exact source fields, URL, and document SHA-256. Corrected cache v5 covers 686 pages and yields 353 structured profile facts (down from the contaminated v3 count of 594); it also retains focal profile-heading context. Regression coverage was added for card isolation and profile headings.
